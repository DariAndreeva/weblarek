# Интернет-магазин «Web-Larёk»

«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

# Архитектура приложения

Ключевые принципы реализации MVP в данном проекте:

- **View не хранит бизнес-состояние.** Все поля классов представления имеют тип `HTMLElement` или его подтипы. Значения других типов (строки, числа, булевы) хранятся только в моделях.

- **View не выполняет валидацию.** Методы валидации отсутствуют в классах форм. Валидация данных происходит централизованно в `BuyerModel` и вызывается из Presenter.

- **Обработчики кликов передаются извне.** Классы карточек принимают колбэки через параметры конструктора, что обеспечивает инверсию управления и позволяет Presenter гибко управлять поведением компонентов.

- **Реактивное обновление UI.** При изменении состояния модели (например, через `buyer.setPayment()`) автоматически эмитится событие (например, `покупатель:изменился`), на которое подписан Presenter. Presenter вызывает методы валидации и обновляет все связанные компоненты View через их сеттеры.

## Слой представления View

Слой View состоит из компонентов, каждый из которых отвечает за отображение конкретного блока разметки. Все компоненты наследуются от базового класса `Component`.

Компоненты View не хранят бизнес-состояние (кроме ссылок на DOM-элементы) и не выполняют валидацию. Они только:

- Отображают данные через сеттеры и метод `render()`
- Генерируют пользовательские события (клики, ввод)
- Принимают обработчики событий через конструктор

Взаимодействие с пользователем осуществляется через генерацию событий, которые перехватываются Presenter и обрабатываются методами моделей и представлений.

## Иерархия компонетнов

1.  Карточки товаров

Три класса карточек имеют общего родителя `ProductCard`, в который вынесен общий функционал (установка изображения, категории, цены, заголовка).

Обработчики кликов передаются в карточки через параметры конструктора **без параметров** (например, `() => void`).

- `ProductCard` — Абстрактный родитель. Отвечает за базовое отображение товара.

- `ProductCardPreview` — Отображает товар в сетке каталога.

  Шаблон: `#card-catalog`.

  Конструктор принимает колбэк `onCardClick`, который вызывается при клике по карточке и эмитит событие `товар:выбран` с ID товара.

  Текст кнопки "В корзину"/"Удалить" устанавливается через сеттер из Presenter на основе данных `CartModel.hasItem()`.

  Методы: `setTitle`, `setCategory`, `setPrice`, `setImage`.

- `ProductCardFull` — Отображает подробную информацию о товаре в модальном окне.

  Сеттер `set price` отвечает **только за блокировку/разблокировку кнопки**.

  Шаблон: `#card-preview`.

  Конструктор принимает колбэк `onButtonClick`, который вызывается при клике на кнопку и эмитит событие `card:buy` с ID товара.

  Presenter сам решает, какое действие выполнить, на основе `CartModel.hasItem()`.

  Методы: `setDescription`, `setBuyButtonText`, `setBuyButtonDisabled`, `setButtonDisabled`.

  Сеттеры позволяют Presenter управлять состоянием кнопки без знания внутренней структуры компонента.

- `ProductCardBasket` — Отображает товар в списке корзины.

  Шаблон: `#card-basket`.

  Конструктор принимает колбэк `onDelete`, который вызывается при клике на кнопку удаления и эмитит событие `товар:удалить`.

  Методы: `setIndex` (порядковый номер).

### 2. Формы

Два класса форм имеют общего родителя `Form`, в который вынесен базовый функционал работы с полями ввода и кнопкой отправки.

Формы не выполняют валидацию. Валидация данных происходит в `BuyerModel` и вызывается из Presenter в обработчике события `покупатель:изменился`.

- `Form` — Абстрактный родитель.

  Содержит флаг `touched`, который отслеживает первое взаимодействие с формой (для UX: ошибки не показываются до первого ввода).

  Не содержит методов валидации.

  Генерирует события:
  - `'форма:изменение'` — при вводе данных в поле или клике по кнопке выбора оплаты.
  - `'форма:отправка'` — при нажатии кнопки отправки (данные отправляются без предварительной валидации, так как кнопка заблокирована при наличии ошибок).

  Сеттер `errors` принимает объект с ошибками, отображает их текст и блокирует/разблокирует кнопку submit.

- `OrderForm` — Форма оформления заказа (выбор оплаты + адрес доставки).

  Шаблон: `#order`.

  Содержит поля `cardButton` и `cashButton` (HTMLButtonElement).

  При клике на кнопки оплаты только эмитит событие `'форма:изменение'` с полем `payment`. **Не меняет стили кнопок самостоятельно.**

  Сеттер `payment` позволяет Presenter подсвечивать активную кнопку через класс `button_alt-active`.

- `PaymentForm` — Форма ввода контактов (email + телефон).

  Шаблон: `#contacts`.

  Содержит поля `emailInput` и `phoneInput`.

3. Модальное окно

`Modal` - Контейнер для отображения всплывающих окон.
Не имеет дочерних классов. Контент внутрь передается через метод `render({ content: HTMLElement })`.

Генерирует событие `модалка:закрыта` при клике на фон или крестик.

4. Прочие компоненты интерфейса

`Header` - Шапка сайта.

Метод:

`setCounter(value: number)` - обновляет счетчик товаров в корзине.

Генерирует событие `корзина:открыта` при клике на иконку корзины.

`Gallery` - Контейнер для списка товаров каталога.

Принимает от Презентера уже готовый массив HTML-элементов (`HTMLElement[]`) и вставляет их в DOM.

Метод:

`render(data: { items: HTMLElement[] }): HTMLElement` — очищает контейнер и вставляет готовые карточки через `replaceChildren`.

`Basket` - Содержимое корзины (список товаров + итоговая сумма).

Принимает от Презентера готовый массив HTML-элементов.

Метод:

`render(data: { items: HTMLElement[], total: number }): HTMLElement` — вставляет готовые элементы карточек в список и отображает итоговую сумму.

Генерирует событие `заказ:начать` при клике на кнопку "Оформить".

`Success` - Экран успешной покупки.
Генерирует событие `успех:закрыто` при закрытии.

### Базовый код

#### Класс Component

Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`

#### Класс Api

Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter

Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` - хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

### Данные

В приложении используются две основные сущности, описывающие данные: товар и покупатель.

`IProduct` - Интерфейс описывает структуру данных товара.

- ``id: string` - уникальный идентификатор товара.
- `title: string` - название товара.
- `description: string` - подробное описание товара.
- `image: string` - ссылка изображения товара.
- `category: string` - категория товара.
- `price: number | null` - цена товара.

`IBuyer` - Интерфейс описывает данные, необходимые для оформление заказа:

- `payment: TPayment` - Способ оплаты.
- `email: string` - Электронная почта.
- `phone: string` - номер телефона.
- `address: string`- адрес доставки.

### Модели данных

Для учета данных в приложение 3 класса, разделённые по смыслу и зонам ответсвенности.
Все модели принимают `events: EventEmitter` в конструктор для генерации событий.

#### Класс CatalogModel

Хранит массив всех товаров и выбранную карточку товара для детального отображения.

constructor(events: EventEmitter) — принимает экземпляр брокера событий для генерации событий при изменении данных.

Поля класса:  
`items: IProduct[]` - массив всех товаров каталога.
`selected: IProduct | null` - Выбранная карточка товара (для отображение в модальном окне).

Метод класса:

- `setItems(items: IProduct[]): void` — сохраняет массив товаров и генерирует событие `'каталог:изменился'`.
- `getItems(): IProduct[]` — возвращает массив всех товаров.
- `getItem(id: string): IProduct | undefined` — возвращает товар по id.
- `setSelected(item: IProduct): void` — сохраняет выбранный товар

#### Класс CartModel

Хранит массив товаров, добавленных пользователем в корзину, и предоставляет методы для управления ими.

Конструктор: `constructor(events: EventEmitter)`

Поля класса:

items: IProduct[] - массив товаров в корзине.

Метод класса:

- `addItem(item: IProduct): void` — добавляет товар, генерирует `'корзина:изменилась'`.
- `removeItem(item: IProduct): void` — удаляет товар, генерирует `'корзина:изменилась'`.
- `clear(): void` — очищает корзину.
- `getTotal(): number` — сумма стоимости.
- `getCount(): number` — количество товаров.

#### Класс BuyerModel

Хранит данные покупателя для оформления заказа и обеспечивает их валидацию.

Конструктор: `constructor(events: EventEmitter)`

Поля класса:

`payment: 'card' | 'cash' | null` — способ оплаты.
`address: string` — адрес доставки.
`email: string` — электронная почта.
`phone: string` — номер телефона.

Методы класса:

- `setPayment`, `setAddress`, `setEmail`, `setPhone` — сохраняют данные и генерируют событие `'покупатель:изменился'`.
- `getData(): IBuyer` — возвращает объект со всеми данными.
- `validate(): Record<string, string>` — проверяет данные, возвращает объект с ошибками (или пустой). **Вызывается из Presenter**, а не из форм.
- `clear(): void` — очищает все данные после успешного заказа.

### Обработчик события "покупатель:изменился"

В Presenter (`main.ts`) реализован обработчик события `покупатель:изменился`, который обеспечивает реактивное обновление UI:

1. Получает актуальные данные через `buyer.getData()`
2. Вызывает `buyer.validate()` для получения ошибок валидации
3. Перерисовывает обе формы (`OrderForm` и `PaymentForm`) через метод `render()` с актуальными данными
4. Подсвечивает активную кнопку оплаты через сеттер `orderForm.payment`
5. Формирует объекты ошибок для каждой формы и передаёт их через сеттер `errors`
6. Сеттер `errors` автоматически блокирует/разблокирует кнопки submit на основе наличия ошибок
7. При необходимости обновляет состояние кнопок в модальных окнах (например, меняет текст на "Удалить из корзины" или "Недоступно").

Это реализует принцип MVP: при изменении состояния модели автоматически обновляется вся связанная вёрстка.

## Слой коммуникации

Для взаимодействия с сервером используется класс `ApiClient`.

#### Назначение

Класс отвечает за получение каталога товаров и отправку оформленных заказов на сервер. Реализован через композицию с базовым классом `Api`.

#### Конструктор

`constructor(api: IApi)` - принимает экземпляр класса, реализующего интерфейс `IApi`, для выполнения HTTP-запросов.

#### Методы

- `getProducts(): Promise<{ items: IProduct[] }>` — получает от сервера объект вида `{ items: [...] }` и возвращает его. Презентер извлекает массив через `response.items`.
- `postOrder(order: IOrder): Promise<IOrderResult>` — выполняет POST-запрос на эндпоинт `/order/`. Принимает объект заказа и возвращает объект с результатом операции (подтверждение покупки).

#### Типы данных

- `IProductsResponse`: структура ответа сервера при получении каталога.
- `IOrder`: расширенный интерфейс `IBuyer`, включающий сумму заказа (`total`) и список ID товаров (`items`).
- `IOrderResult`: структура ответа сервера при успешном создании заказа.
